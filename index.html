DOCUMENTATION / WORKFLOW

Know what the tool can do.

Practical notes on reconstruction, rigging, motion and formats.

01

Images are references, not a scan

Two orthogonal views constrain a rough silhouette but leave the back, depth variation, occluded limbs and clothing folds ambiguous. The fitting workflow makes a clean editable base and gives you proportion controls. For photogrammetry, capture overlapping views around the subject; each surface should appear in several images.

Gaussian splats are excellent for novel-view rendering, but a splat cloud is not automatically a watertight, skinned game mesh.
02

From scan to game mesh

For a real scan, use COLMAP or AliceVision/Meshroom to estimate cameras and reconstruct geometry. Clean the result, remove floating fragments, remesh/retopologize, unwrap UVs, bake textures and validate the surface. Import the resulting GLB/OBJ/PLY here for viewing; complex cleanup remains a desktop DCC task.

COLMAP documentation ↗AliceVision / Meshroom ↗
03

Rigging & deformation

The generated humanoid uses a named 22-bone skeleton and four-influence skin weights. Joint limits keep editor poses in configured ranges. For production work, inspect shoulder, hip, elbow and knee deformation; add twist bones, corrective shapes, facial rigs or custom secondary motion where needed.

Blender (free DCC) ↗
04

Motion & export

Procedural motion clips animate joint rotations. The source preview displays the selected base action; the result preview displays the base plus an additive, body-part-masked layer. GLB export bakes the built-in and custom clips at 30 fps. External clips need to be retargeted in Blender or your game engine; this page does not yet retarget animations from unrelated skeletons.

Khronos glTF specification ↗CC0 game animation reference pack ↗
05

Cost & privacy model

There are no paid APIs, accounts, AI tokens or hosted GPU calls. Images and project data stay in browser memory / IndexedDB unless you explicitly download them. Three.js is loaded from a free public CDN, so the first launch requires internet access. The actual reconstruction workload is not secretly sent to a server. Heavy photogrammetry and neural Gaussian-splat training still require a capable local PC and suitable open-source tools; this page does not promise phone-based neural reconstruction.

For an actual high-fidelity scan, capture more images and process them locally in Meshroom/COLMAP, or use a local GPU workflow. Then import the resulting mesh for inspection and packaging. This page does not currently auto-rig imported meshes or retarget their animation clips onto the generated humanoid skeleton.
